# 简历评分与审查方法论

本文档定义 resume-optimizer 技能使用的百分制评分模型与 40+ 项审查清单。SKILL.md 仅在触发后加载本文件。

## 一、五维度百分制评分（总分 100）

| 维度 | 权重 | 评估要点 |
|------|------|----------|
| 内容质量 | 30 | 量化成果密度、个人优势清晰度、数据准确性、商业成果可验证性 |
| 结构与排版 | 25 | 段落组织、格式统一性、篇幅控制（建议 ≤ 3 页 A4）、层级清晰度 |
| 语言与语法 | 20 | 强动词覆盖、中英文混排空格规范、量化成果加粗层次 |
| ATS 优化 | 15 | 结构化关键词模块、无年龄/隐私暴露、`##`/`###` 标题可解析 |
| 影响力与印象 | 10 | 职业上升轨迹、差异化竞争力、价值主张表达力 |

等级映射：A+ (90-100) / A (85-89) / B+ (80-84) / B (75-79) / C (65-74) / D (50-64) / F (<50)。

评分报告必须包含：总分与等级、五维度明细得分、Top 3 优势、优先级改进项（含 Before→After 示例）、5 步行动计划。

## 二、40+ 项审查清单（8 大类）

逐项标注 ✅ 通过 / ❌ 缺失 / ⚠️ 需改进。

### 1. 联系方式
- [ ] 姓名、手机、邮箱齐全且格式正确
- [ ] 求职意向 / 目标岗位明确
- [ ] 不暴露身份证号、详细住址、薪资等敏感信息

### 2. 摘要 / 个人简介
- [ ] 开场为结果导向（量化经验年数 + 核心品类 + 关键成果）
- [ ] 分行要点展示，非整段叙述
- [ ] 软素质用 1 行关键词标签，不堆砌万能形容词句
- [ ] 技术能力已结构化归入"核心能力"模块，不在此重复罗列

### 3. 工作经历
- [ ] 公司 | 岗位 | 时间 三段式格式统一
- [ ] 倒序排列，时间连续无断档（断档需向用户确认）
- [ ] 每条以强动词开头（主导 / 组建 / 建立 / 统筹 / 优化）
- [ ] 量化成果加粗高亮，含具体数字（流水 / 留存 / ROI / 团队规模）
- [ ] 公司-项目映射关系准确（**必须逐项与用户核对，不得盲信原简历**）
- [ ] 业绩归属正确（某数据/团队/流程属于哪个公司，需确认）

### 4. 教育背景
- [ ] 学校、专业、学历、时间完整
- [ ] 资深候选人（≥10 年经验）放简历末尾，工作经历优先
- [ ] 跨专业背景用一句话转为差异化叙事，不喧宾夺主

### 5. 核心能力 / 技能
- [ ] 独立结构化模块（表或分组），供 ATS 提取关键词
- [ ] 分类覆盖产品研发 / 项目管理 / 技术工具 / 运营增长 / IP 运作等
- [ ] 含行业通用关键词（Unity、CocosCreator、PMO、BI、AIGC 等）
- [ ] 同义能力去重（如"数据采集"按产品级/平台级归属到正确行）
- [ ] AI 能力（如 SDD/TDD/AIGC）单独成项以形成差异化

### 6. 语言与语法
- [ ] 中英文 / 数字间加半角空格（如 `ROI 3.42%`、`Unity`）
- [ ] 无"负责……负责……"重复句式，句式多样化
- [ ] 被动语态改主动（"作为主策划负责"→"主导"）
- [ ] 无口语化 / 冗余括号说明

### 7. 排版
- [ ] 篇幅 ≤ 3 页 A4
- [ ] 各公司经历之间段间距一致且充足（建议 ≥ 6mm）
- [ ] 大段落（如章节）间距为公司的 1.5 倍
- [ ] 单家公司条目 ≤ 6 条 bullet，超限则合并精简
- [ ] 打印分页不切断单家公司条目（`page-break-inside: avoid`）

### 8. ATS 兼容性
- [ ] 无图片化文字（标题/成果均为可选中文本）
- [ ] 无表格跨页错乱、无特殊字体依赖
- [ ] 岗位关键词（如"目标岗位名"）在标题与摘要中重复出现
- [ ] 无年龄、出生年份、照片等可能触发初筛过滤的字段

## 三、关键经验（来自实战复盘，必读）

1. **绝不盲信原简历数据。** 年限、公司-项目映射、业绩归属、流水口径四类最易出错，必须在动笔前逐项与用户核对。
2. **流水口径必须区分"月千万级"与"总千万级"。** 累计流水求和时，月流水按"月 × 月数"折算为总量，否则会大幅低估（例：月千万级 × 半年 ≈ 数千万量级）。
3. **个人评价拆解法**：技术能力 → 并入核心能力表；软素质 → 1 行标签；剔除"逻辑思维强""团队协作"等万能句（由经历本身证明）。
4. **PDF 导出（中文）必须用 ASCII 路径**：Edge headless `--print-to-pdf` 在非 ASCII 路径下产出位置异常，需先复制到 ASCII 临时副本再导出。
5. **默认流程：先预览 A4 分页、再导出 PDF**，交付前先给 HTML 预览（可按用户偏好调整）。

## 四、Before→After 示例

**Before（弱）：**
> 负责某款游戏的运营工作，取得了一些成绩。

**After（强）：**
> **主导『某款长线运营产品』2+ 年，累计流水达千万级**；上线 2 个月实现单日 ¥X 万、单月 ¥Y 万营收，助力项目组升级为事业部。
